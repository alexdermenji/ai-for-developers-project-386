# Правила проекта

Учебный проект Хекслета: сервис записи на 30-минутные звонки.
Стек: TypeScript, React, Vite, Mantine, Express, Vitest, ESLint. Node.js 24.

## Формат сотрудничества

- Общаться на русском и объяснять понятия простым языком.
- Идти по заданию курса небольшими шагами, опираясь на актуальную официальную документацию инструментов.
- По умолчанию пользователь сам редактирует файлы и запускает команды; агент объясняет действия, даёт команды и помогает проверить результат.
- Изменять файлы, запускать команды, делать коммиты и отправлять изменения самостоятельно только по явной просьбе пользователя в соответствующем объёме.
- Не переходить к следующему учебному этапу до разбора результата текущего.

## Структура

- `src/` — интерфейс React; `public/` — статические файлы.
- `server/app.ts` — приложение Express и маршруты; `server/index.ts` — запуск сервера.
- `server/app.test.ts` — дымовой тест: запуск на свободном порту, HTTP-запрос, закрытие сервера.
- `.github/workflows/ci.yml` — линтер, тесты и сборка; `release-please.yml` — автоматизация релизов.

## Команды из корня проекта

- Установка: `npm ci`.
- Фронтенд: `npm run dev` (адрес выводится в терминале).
- Бекенд в отдельном терминале: `node server/index.ts` (порт 3000).
- Тесты: `npm test`.
- Линтер: `npm run lint`.
- Сборка: `npm run build` (сейчас собирает фронтенд в `dist/`, не бекенд).
- Просмотр сборки фронтенда: `npm run preview`.
- Перед отправкой изменений: `npm run lint && npm test && npm run build`.

## Git и проверки

- Сообщения коммитов — Conventional Commits: `feat:`, `fix:`, `docs:`, `ci:`, `chore:` с кратким описанием.
- Release Please управляет версией и changelog через release-PR; релиз сам по себе не является деплоем.
- Не коммитить `node_modules/`, `dist/` и секреты. Сохранять `package-lock.json` при изменении зависимостей.
- Не изменять и не удалять `.github/workflows/hexlet-check.yml`.
